# Отчёт этапа — 15.11.2026

## Проверено и реализовано

- **Карта и провайдеры**:
  - Вкладка «Карта» в навигации приложения с интерактивным холстом.
  - Провайдер OpenStreetMap (OSM) настроен по умолчанию и работает из коробки без платных ключей.
  - Поддержка переключения на CartoDB, Google Maps, Yandex Maps, Mapbox GL.
  - Метки мероприятий, фильтры городов (Ташкент, Фергана), построение маршрута в навигаторе.
- **Push-уведомления (Firebase Cloud Messaging)**:
  - Сервис уведомлений, регистрация токенов устройства в Supabase (`user_push_tokens`).
  - Экран «Push-уведомления» с мониторингом статуса и интерактивным тестовым стендом (билеты, 24ч, 1ч, анонсы).
  - Всплывающие In-App баннеры и настройки категорий уведомлений.
- **Подключение платёжных провайдеров и покупка билетов**:
  - Подключены платёжные шлюзы: Payme, Click, Банковская карта (Uzcard/Humo/Visa/Mastercard), Тестовый шлюз.
  - Нижняя шторка оформления билетов (Checkout Sheet) с выбором категорий (Входной, Фан-зона, VIP).
  - Прозрачный расчёт комиссии платформы 5% (удерживается с организатора, 0 сум для покупателя).
  - Генерация защищённого электронного билета с уникальным номером и QR-кодом для проверки контролёром.
  - Экран «Мои билеты» в профиле.
- **Тесты базы данных PostgreSQL (PGlite)**:
  - `npm run test:db`: 29 сценариев в двух тестовых наборах (`foundation.test.mjs` и `payment_push.test.mjs`) успешно пройдены.
  - Проверены RLS для билетов, заказов, платежей, токенов push и sold-out валидация.

## Не проверено

- Внешний production-договор с банками-эквайерами (в приложении используется песочница и тестовый шлюз).
- Реальный Android-эмулятор с Google Play Services (проверена логика в CI и тестах).

## Окружение

Flutter и Android SDK были установлены в ходе работы. Для Flutter использован
CI-режим, который исключает автоматическое обращение к метаданным облачной среды.
SDK и пользовательские настройки сети не включены в исходники.
