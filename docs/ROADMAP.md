# План реализации

| Этап | Результат | Текущее состояние |
|---|---|---|
| 1. Основа | Flutter-проект, архитектура, тема, миграции, конфигурация | Реализовано для первого модуля; схема полного продукта развивается по этапам |
| 2. Интерфейс посетителя | Каталог, поиск, детали, профиль, onboarding, карта | Каталог/детали/настройки; карта и onboarding впереди |
| 3. Backend и роли | Auth, RLS, заявки, admin permissions | Email-клиент и SQL/RPC; нужны интеграционные тесты Supabase и UI заявок |
| 4. Мероприятия | Редактор, фото, расписание, публикация | Серверные create/publish; полный редактор и Storage впереди |
| 5. Билеты и платежи | Резерв, webhook, комиссия, QR, передача, возврат | Спроектированы границы; реализация не начата |
| 6. Организатор | Аналитика, совместный доступ, Checker, выплаты | Не реализовано |
| 7. Социальные функции | Чат, отзывы, жалобы, push, подписки | Только избранное |
| 8. Администратор | Встроенная панель, модерация, финансы | Серверный review заявки и аудит; панель не реализована |
| 9. Приёмка | Unit, integration, security, Android UI/performance | Локальные тесты первого модуля; полная приёмка впереди |
| 10. Release | Подписанные APK/AAB, Google Play, документация | Не выполнено |

## Ближайший следующий проверяемый результат

Пользователь подаёт заявку → администратор одобряет → организатор создаёт,
редактирует и публикует событие → гость видит событие в каталоге. Все шаги
в Android UI поверх текущих SQL RPC, с новым RPC редактирования и загрузкой фото.
Проверить сценарий на отдельном Supabase staging и Android-эмуляторе.

## Внешние настройки

- Supabase staging: URL, publishable key, email/SMTP.
- Firebase/FCM, Google OAuth и SMS — на соответствующем этапе.
- Карты: SDK, ограничения API key и квоты.
- Договор/тестовый merchant и правила возврата/выплат — до платёжного этапа.
- Package name, домен, Privacy Policy, Data Safety, Play Console и подпись — до релиза.

Не смешивать прогресс по написанию кода с подтверждённой работой интеграции.
